## Decision brief

Keep #62 in the unscheduled backlog as a **reserve-only v2.5.0 candidate**. Do not select it for a sprint or claim that Excel automation works. For one bounded feasibility assessment, use the existing *Excel Executive Dashboard Workbook* specification as the candidate, not the broad automation suite. It describes a reporting layout and illustrative values, but there is no corresponding dashboard `.xlsx`; the promised download is not present.

The source inventory found 18 tracked `.xls`/`.xlsx` files, all in sanitized-template staging or the separate #319 test fixtures; none is an advertised executive dashboard. There are five standalone `.bas` files, but no `.xlsm`/`.xlam`; the Power Query and VBA dashboard material is mostly snippets. The advanced guide advertises 20 relative files, 19 missing, including `project-status-automation.md`. A separate staged project-management workbook is not a dashboard and its metadata is not runtime evidence.

The runner is Linux and has neither Excel nor LibreOffice. Therefore no Excel editing, recalculation, VBA compilation/run, macro-trust test, or Power Query refresh was performed. A proposed first test target is Excel desktop for Windows 11 with Microsoft 365 Apps (record the exact build), using a macro-free local-data fixture; this is **not** a current support claim. Michael must decide whether to retain that narrow candidate and its test boundary after the v2.5 core search/onboarding capacity review. #1556 targets January 22, 2027 subject to readiness; #62 has no sprint or release-milestone assignment, and publication needs separate authorization.

### Proposed executable Excel test steps

1. After an owner-approved workbook exists, use a clean Windows 11 VM with Microsoft Excel desktop (Microsoft 365 Apps); record product, channel, version/build, bitness, and OS build. The proposed baseline is a test target only, not validated support.
2. Use a copy of the workbook with macros disabled. Do not add a repository, downloads, or user-data folder to Trusted Locations. Do not connect accounts or external services.
3. Enter the one-row fixture into the documented input table. Recalculate in Excel and compare the three expected results above, using the workbook’s displayed sign convention.
4. Repeat with blank forecast, zero budget, a blank required ID, and a malformed date. Record exact displayed error/abstention behavior; no unapproved default values.
5. Save, close, reopen, and compare the values. If the chosen design contains no Power Query connection, record “no refresh configured”; if a future owner-approved design adds a local CSV query, separately test Data → Refresh All after changing that CSV. Do not label this real-time or scheduled refresh.
6. Preserve a sanitized workbook copy, the synthetic input, expected/actual results, screenshots or a test log, and exact environment details. Request separate human review of formula definitions, navigation, accessibility, and whether the report answers the intended decision.
