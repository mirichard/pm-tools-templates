# Principle Application Anti-Patterns

| Anti-pattern | Why it fails | Corrective behavior |
|---|---|---|
| Metadata theater | Tags exist but do not affect decisions | Link each annotation to concise practical rationale and usage guidance |
| Value equals output | Completion is mistaken for realized benefit | Define outcome measures, owners and post-delivery review |
| Rebaseline to green | Original underperformance is erased | Preserve original baseline and approved-change history |
| Stakeholder broadcast | One-way communication is labeled engagement | Identify decisions requiring stakeholder input and close feedback loops |
| Tailoring by omission | Required control disappears without rationale | Record context, risk, authorization and retained minimum control |
| Maximum governance | Every project receives the heaviest process | Scale assurance to exposure while retaining non-negotiable safeguards |
| Metric without source | Precision is claimed without reliable evidence | Record source, as-of date, formula and confidence |
| Template as substitute for judgment | Completion becomes the goal | State when not to use and the decision the artifact supports |
| Self-approval | Author review is represented as independent assurance | Record self-validation honestly and obtain a separate approver |
| Lessons archive | Findings are stored but never change future work | Assign actions and link learning to standards, estimates and planning |
