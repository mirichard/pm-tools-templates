# Empathy Map Template

## Overview

An empathy map is a visual tool that helps teams understand their users' perspective, emotions, and experiences. It captures what users think, feel, see, say, do, and their pain points and gains.

## Usage Guidelines

### When to Use This Template
- At the beginning of design thinking workshops
- During user research synthesis
- When developing user personas
- Before ideation sessions
- When validating assumptions about users

### How to Fill Out
1. **Gather Data**: Use interviews, observations, surveys, and existing research
2. **Involve Team**: Complete as a team exercise for diverse perspectives
3. **Be Specific**: Use actual quotes and concrete behaviors
4. **Stay Factual**: Base insights on evidence, not assumptions
5. **Update Regularly**: Empathy maps should evolve with new insights

### Tips for Success
- Focus on one specific user type or scenario per map
- Use the user's own words and language
- Look for patterns and contradictions
- Identify the most critical pain points and gains
- Validate assumptions through user research

## Examples

### Example 1: Project Manager User
**Context**: Managing multiple projects with tight deadlines

**Key Insights:**
- **Thinks**: Constantly worried about missing deadlines and budget overruns
- **Feels**: Overwhelmed by competing priorities, frustrated by lack of visibility
- **Sees**: Too many spreadsheets, endless email chains, team confusion
- **Says**: "I need better visibility into project status"
- **Does**: Checks status multiple times daily, attends numerous meetings
- **Hears**: Teams complaining about process overhead, executives asking for updates

**Top Pain Point**: Lack of real-time project visibility
**Top Gain**: Automated status reporting that saves time

### Example 2: End User of New System
**Context**: Learning to use a new project management tool

**Key Insights:**
- **Thinks**: Worried about learning curve and productivity impact
- **Feels**: Anxious about change, skeptical about benefits
- **Sees**: Complex interface, many features they don't understand
- **Says**: "Why can't we just use what we had before?"
- **Does**: Tries to work around the new system, asks colleagues for help
- **Hears**: Mixed reviews from early adopters, management pushing adoption

**Top Pain Point**: Complex learning curve
**Top Gain**: Easy-to-use interface with quick wins
